# 구독한잔해

사용자가 등록한 구독 정보를 관리하고, 결제 주기를 월 단위로 환산하여 지출을 확인하며, 장기간 사용하지 않은 구독 탐지, 체감 지출 리포트 및 공유 구독의 1인당 부담액 계산 기능을 제공하는 프로그램


## 0. 사양

- Python 3.13.7 기반
- CLI(Command Line Interface) 프로그램
- 프로그램 실행 중 구독 정보는 subscriptions 딕셔너리에서 관리
- 구독 정보는 JSON 파일을 이용하여 저장 및 불러오기


## 1. 실행 방법 및 실행 위치

### 1.1 실행 위치

프로그램은 `main.py`가 존재하는 `구독한잔해 프로젝트2` 폴더에서 실행한다.

프로젝트 구조에서 다음 위치의 `main.py`가 프로그램 실행 파일이다.

`구독한잔해 프로젝트2/main.py`


### 1.2 VSCode에서 실행

1. VSCode에서 `구독한잔해 프로젝트2` 폴더를 연다.
2. 폴더 안에 있는 `main.py` 파일을 연다.
3. VSCode의 실행 버튼을 눌러 프로그램을 실행한다.


### 1.3 터미널에서 실행

터미널에서 `구독한잔해 프로젝트2` 폴더로 이동한 뒤 다음 명령어를 입력한다.

```bash
python main.py
```

프로그램이 정상적으로 실행되면 다음 메인 메뉴가 출력된다.

```text
===== 구독한잔해 =====
1. 구독 관리
2. 결제 주기 정규화
3. 체감 지출 리포트
4. 분담비용 계산기
0. 저장 후 종료
```

프로그램 실행 시 기존에 저장된 구독 정보가 있으면 JSON 파일에서 불러와 사용한다.


## 2. 메뉴별 기능 설명

### 2.1 1번 - 구독 관리

사용자가 이용하고 있는 구독 서비스를 등록, 조회, 삭제하는 메뉴이다.

구독 관리 메뉴는 다음과 같이 구성된다.

```text
===== 구독 관리 =====
1. 구독 등록
2. 구독 조회
3. 구독 삭제
0. 뒤로가기
```


#### 1) 구독 등록

새로운 구독 서비스를 등록한다.

다음 정보를 입력받는다.

- 서비스명
- 요금
- 결제 주기
- 다음 결제 예정일
- 카테고리
- 마지막 이용일
- 무료체험 종료일
- 공유 인원수

입력값을 검증한 뒤 정상적인 값이면 subscriptions에 구독 정보를 저장한다.

잘못된 요금, 결제 주기, 날짜, 공유 인원수 등이 입력되면 오류 메시지를 출력하고 다시 입력하도록 한다.


#### 2) 구독 조회

현재 등록되어 있는 구독 정보를 출력한다.

구독 조회 후 해지 후보 탐지 기능이 자동으로 실행된다.

마지막 이용일과 현재 날짜를 비교하여 30일을 초과하여 이용하지 않은 구독을 해지 후보로 표시한다.

무료체험 종료일이 있는 경우 남은 기간을 D-day로 출력한다.

등록된 구독이 없는 경우 `"등록된 구독이 없습니다."`라는 메시지를 출력한다.


#### 3) 구독 삭제

삭제할 서비스명을 입력받아 해당 구독을 삭제한다.

입력한 서비스명이 존재하는 경우 해당 구독 정보를 삭제한다.

등록되지 않은 서비스명을 입력한 경우 `"해당 서비스가 존재하지 않습니다."`라는 메시지를 출력한다.


#### 0) 뒤로가기

구독 관리 메뉴를 종료하고 메인 메뉴로 돌아간다.


### 2.2 2번 - 결제 주기 정규화

서로 다른 결제 주기를 가진 구독 비용을 월 기준 비용으로 환산한다.

결제 주기별 월 환산 방법은 다음과 같다.

- 월간 : 입력된 요금을 그대로 월 비용으로 사용
- 연간 : 요금 ÷ 12
- 4주 : 요금 × 13 ÷ 12

각 구독의 월 환산 비용을 계산한 뒤 다음 정보를 출력한다.

- 각 서비스의 월 환산 비용
- 전체 월 구독 지출
- 카테고리별 월 구독 지출

등록된 구독이 없는 경우 `"등록된 구독이 없습니다."`라는 메시지를 출력한다.


### 2.3 3번 - 체감 지출 리포트

등록된 모든 구독의 월 환산 비용을 이용하여 연간 예상 구독 지출액을 계산한다.

계산된 연간 예상 지출액을 커피 한 잔 5,000원을 기준으로 환산하여 사용자가 구독 지출 규모를 쉽게 확인할 수 있도록 출력한다.

출력 내용은 다음과 같다.

- 연간 예상 구독 지출액
- 커피 가격 기준 환산 잔 수


### 2.4 4번 - 분담비용 계산기

등록되어 있는 구독 서비스 중 하나를 선택하여 1인당 월 실부담액을 계산한다.

선택한 서비스의 요금을 월 기준 비용으로 환산한 뒤 저장되어 있는 공유 인원수로 나누어 계산한다.

분담비용 계산 과정은 다음과 같다.

`월 환산 비용 ÷ 공유 인원수 = 1인당 월 실부담액`

등록되지 않은 서비스명을 입력한 경우 `"해당 서비스가 존재하지 않습니다."`라는 안내 메시지를 출력한다.

등록된 구독이 없는 상태에서 실행하면 `"등록된 구독이 없습니다."`라는 안내 메시지를 출력하고 메인 메뉴로 돌아간다.


### 2.5 0번 - 저장 후 종료

현재 subscriptions에 저장되어 있는 구독 정보를 JSON 파일에 저장한다.

저장이 완료되면 프로그램을 종료한다.

다음에 프로그램을 다시 실행하면 저장되어 있는 구독 데이터를 불러와 사용할 수 있다.


## 3. 파일 저장 구조

구독 정보는 `subscriptions.json` 파일에 저장한다.

서비스명을 Key로 사용하고 각 서비스의 정보를 하위 데이터로 저장한다.

저장되는 데이터 항목은 다음과 같다.

- `cost` : 요금
- `cycle` : 결제 주기
- `next_payment` : 다음 결제 예정일
- `category` : 카테고리
- `last_used` : 마지막 이용일
- `trial_end` : 무료체험 종료일
- `shared_count` : 공유 인원수

프로그램 실행 중 구독 정보는 subscriptions 딕셔너리에서 관리한다.

프로그램 종료 시 subscriptions의 구독 정보를 JSON 파일에 저장하며, 프로그램을 다시 실행하면 기존 JSON 데이터를 불러온다.


## 4. 테스트 방법

### 4.1 테스트 1 - 정상적인 구독 관리 및 비용 확인 시나리오

다음 6개의 구독 정보를 이용하여 테스트한다.

| 서비스명 | 요금 | 결제 주기 | 다음 결제 예정일 | 카테고리 | 마지막 이용일 | 무료체험 종료일 | 공유 인원수 |
| --- | ---: | --- | --- | --- | --- | --- | ---: |
| 넷플릭스 | 17,000원 | 월간 | 2026-09-15 | OTT | 2026-08-20 | - | 2 |
| 유튜브 프리미엄 | 14,900원 | 월간 | 2026-09-20 | 영상 | 2026-09-01 | - | 1 |
| Microsoft 365 | 119,000원 | 연간 | 2027-03-01 | 생산성 | 2026-08-10 | - | 1 |
| 멜론 | 10,900원 | 월간 | 2026-09-18 | 음악 | 2026-07-25 | - | 1 |
| 테스트 4주 구독 | 12,000원 | 4주 | 2026-09-25 | 기타 | 2026-09-05 | - | 1 |
| 테스트 OTT 구독 | 10,000원 | 월간 | 2026-09-22 | OTT | 2026-08-01 | 2026-09-20 | 1 |

1. 개발자가 테스트 기준일을 2026-09-09로 정하고, 구독이 없는 상태에서 프로그램을 실행한다.

2. 구독 등록 기능으로 표의 6개 구독에 대한 8개 항목을 입력한다. 무료체험 종료일이 없는 경우 입력을 생략하고 등록 완료 메시지를 확인한다.

3. 구독 조회를 선택하여 6개 구독이 출력되고, 해지 후보 탐지가 자동으로 실행되는지 확인한다.

4. 멜론(46일)과 테스트 OTT 구독(39일)만 해지 후보로 표시되고, 정확히 30일이 지난 Microsoft 365는 제외되는지 확인한다. 테스트 OTT 구독의 무료체험 알림은 D-11인지 확인한다.

5. 결제 주기 정규화를 선택하여 전체 월 지출이 약 75,716.67원이고, 같은 OTT 카테고리의 비용이 27,000원으로 합산되는지 확인한다.

6. 체감 지출 리포트를 선택하여 연간 예상 지출액 908,600원과 커피 환산 결과 181.72잔이 출력되는지 확인한다.

7. 분담비용 계산에서 넷플릭스를 선택하여 저장된 공유 인원수 2명으로 계산한 월 실부담액 8,500원이 출력되는지 확인한다.

8. Microsoft 365를 삭제하고 다시 조회하여 나머지 5개 구독만 남아 있는지 확인한다.


### 4.2 테스트 2 - 잘못된 입력 및 대체 흐름 시나리오

1. 개발자가 구독이 없는 상태에서 조회와 결제 주기 정규화를 선택하여 `"등록된 구독이 없습니다."`라는 안내가 출력되는지 확인한다.

2. 구독 등록에서 서비스명에 디즈니플러스를 입력하고, 요금에 `만원`과 `-9900`을 차례로 입력하여 각각 재입력을 안내하는지 확인한다.

3. 요금에 `9900`, 결제 주기에 `매주`를 입력하여 허용된 결제 주기를 안내하는지 확인한 뒤 월간으로 다시 입력한다.

4. 다음 결제 예정일에 `2026/09/20`과 `2026-02-30`을 차례로 입력하여 각각 재입력을 안내하는지 확인한 뒤 `2026-09-20`을 입력한다. 카테고리와 마지막 이용일은 정상 입력하고 무료체험 종료일은 생략한다. 공유 인원수에 `두명`, `0`, `1.5`를 차례로 입력하여 등록되지 않고 재입력을 안내하는지 확인한다.

5. 공유 인원수에 `2`를 입력하여 등록을 완료한다. 같은 서비스명을 다시 등록하려고 할 때 중복 안내가 나오고 기존 정보가 유지되는지 확인한다.

6. 분담비용 계산에서 디즈니플러스를 선택하여 저장된 2명을 기준으로 월 실부담액 4,950원이 출력되는지 확인한다.

7. 등록되지 않은 웨이브를 삭제하려고 할 때 안내 메시지가 출력되는지 확인한 뒤, 디즈니플러스를 삭제하여 정상적으로 제거되는지 확인한다.


### 4.3 테스트 3 - 데이터 저장 및 재실행 시나리오

1. 개발자가 구독이 없는 상태에서 테스트 1의 6개 구독 정보를 모두 등록하고 프로그램을 정상 종료한다.

2. JSON 파일을 열어 6개 서비스와 각 서비스의 7개 속성이 저장되고, 생략한 무료체험 종료일은 null로 기록되는지 확인한다.

3. 프로그램을 다시 실행하고 별도의 등록 없이 기존 6개 구독이 조회되는지 확인한다.

4. 불러온 날짜로 해지 후보와 무료체험 알림이 계산되고, 넷플릭스의 저장된 공유 인원수 2명으로 월 실부담액 8,500원이 출력되는지 확인한다.

5. Microsoft 365를 삭제하고 정상 종료한 뒤 다시 실행하여, 삭제된 구독은 나타나지 않고 나머지 5개 구독은 유지되는지 확인한다.
